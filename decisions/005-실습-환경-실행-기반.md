# 005. 실습 환경 실행 기반: Ubuntu 24.04 + kubeadm 1.35 + Sysbox

- 상태: 채택 (VM 사양만 대체됨 (006))
- 날짜: 2026-11-02

## 배경

실습 환경은 학습자마다 Pod 하나를 만들고, 그 안에서 Challenge의 Docker Compose(공격 대상 앱, DB)를 띄운다. 기획서 초안의 제안이다. Pod 안에서 privileged 없이 Docker를 돌리려면 Sysbox 같은 런타임이 필요하다.

2026-11-02에 지금 개발 클러스터와 Sysbox v0.7.1 설치 조건을 대조했다. 클러스터는 SSH로 접속해 실측했고, 설치 조건은 공식 문서와 `sysbox-deploy-k8s.sh`에서 확인했다.

| 항목 | 지금 개발 클러스터 | Sysbox 설치 조건 |
|---|---|---|
| Kubernetes | v1.37 (Minikube v1.39.0, docker 드라이버) | v1.32~v1.35. 다른 버전이면 설치 스크립트가 멈춘다 |
| 노드 | Rocky 9.8 VM 안의 컨테이너(kicbase v0.0.51, Debian 12) | 공식 지원 노드 OS는 Ubuntu 18.04~24.04. 컨테이너 노드에 대한 언급은 없다 |
| 커널 | 5.14 (Rocky) | 설치 검사는 Debian 계열 5.5 이상. shiftfs 없이 5.12~6.2면 일부 파일시스템에서 ID-mapped mount가 안 된다 |
| containerd | 2.3.4 | 2.0.5 이상. 아니면 CRI-O를 대신 설치한다 |
| 자원 | 2 CPU / 3GB | 노드당 4 CPU / 4GB 권장 |

## 선택지

1. Ubuntu Server 24.04 VM을 새로 만들고, kubeadm으로 Kubernetes 1.35를 설치한 뒤 Sysbox를 얹는다.
2. 지금 Rocky VM에서 Minikube를 1.35로 다시 만들고, VM 자원을 늘려 Sysbox를 얹는다.
3. Sysbox를 쓰지 않는다. Challenge의 서비스를 일반 Pod로 띄우고 재빌드는 따로 설계한다.

## 결정

1번을 택한다.

- VM: VirtualBox, Ubuntu Server 24.04 LTS, 6 vCPU / 12GB / 80GB, 네트워크는 NAT + Host-only
- Kubernetes: kubeadm 1.35, 단일 노드
- 런타임: containerd 2.0.5 이상, Sysbox(`sysbox-deploy-k8s`)
- CNI: Calico
- 실습 환경: 학습자마다 `runtimeClassName: sysbox-runc` Pod 하나. 그 안에서 Docker Compose로 Challenge를 띄운다

## 이유

- 1번만 Sysbox 공식 지원 조합이다. Ubuntu 24.04는 커널 6.8이라 shiftfs가 필요 없다.
- 2번은 버전을 바꾸면 설치 검사는 통과한다. 하지만 컨테이너 노드와 Rocky 커널 조합은 시험된 기록이 없다. 막히면 원인을 찾기 어렵고, 2달 일정에서 그 시간이 가장 큰 위험이다.
- 1번은 노드가 실제 서버라 운영 구조와 같다. 30명 설계에서는 `kubeadm join`으로 노드를 붙인다.
- 3번은 런타임 문제가 없지만 재빌드와 초기화를 새로 설계해야 한다. "Challenge는 Compose 프로젝트"라는 product.md 정의도 바뀐다.
- k3s는 설치가 더 쉽지만 Sysbox 문서의 시험 목록에 없다.
- Calico: Default Deny를 NetworkPolicy로 걸어야 하므로 NetworkPolicy를 지원하는 CNI가 필요하다.

## 결과

- 개발 클러스터가 Minikube(v1.37)에서 새 VM의 kubeadm(1.35)으로 바뀐다. 기존 Rocky VM은 학습 기록용으로 남긴다.
- 호환표상 client-java 27.0.x와 Kubernetes 1.35는 같은 API(✓)다. [ADR 001](001-kubernetes-client-버전.md)의 결정은 바꾸지 않는다. 실제 호출은 클러스터를 구성한 뒤 확인한다.
- Kubernetes 1.35의 패치 지원은 v1 마감 직후(2027년 초)에 끝난다. Sysbox가 새 버전을 지원하면 올린다.
- Ubuntu 24.04 기본 containerd가 2.0.5보다 낮으면 Docker 저장소의 `containerd.io` 2.x를 쓴다.
- 첫 확인 작업: Sysbox Pod 안에서 `docker compose up`(nginx + DB)이 되는지, 환경이 준비되기까지 몇 초 걸리는지 잰다. 안 되면 그 오류를 근거로 새 ADR을 쓰고 3번을 다시 검토한다.
