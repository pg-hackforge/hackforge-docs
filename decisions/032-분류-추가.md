# 032. 분류 추가

- 상태: 채택
- 날짜: 2026-11-27

## 배경

문제 분류는 12개로 시작했다([ADR 020](020-문제-정보와-목록-API.md)). 앞으로 만들 문제 목록을 정하면서([roadmap.md](../roadmap.md) "문제 목록"), PortSwigger Web Security Academy와 OWASP Top 10에서 자주 다루는데 12개 분류에 없는 주제를 살펴봤다.

| 주제 | 판단 |
|---|---|
| SSTI(서버 템플릿 인젝션) | 자주 나오고 언어마다 템플릿 엔진이 달라 여러 언어로 내기 좋음 |
| NoSQL Injection | MongoDB를 쓰는 Node.js 서비스에서 흔함. SQL Injection과 대비됨 |
| 비즈니스 로직(동시 요청 경쟁 상태 포함) | 쿠폰 중복 사용, 음수 수량 등. 도구로 찾기 어려워 교육 가치가 큼 |
| 보안 설정 오류(CORS, 기본 계정, 디버그 모드) | OWASP 상위 항목. 정보 노출과 일부 겹침 |
| Prototype Pollution | Node.js에만 있음 |
| LLM 프롬프트 인젝션 | 실습 Pod는 외부 통신이 막혀 모델을 Pod 안에서 돌려야 하는데 디스크 2Gi에 들어가지 않음 |

## 선택지

1. 12개 그대로
2. 앞의 셋만 더함
3. LLM 프롬프트 인젝션을 뺀 다섯을 더함

## 결정

3으로 한다(2026-11-27 사람이 결정). 분류는 17개가 된다.

| 키 | 이름 |
|---|---|
| `ssti` | SSTI |
| `nosql-injection` | NoSQL Injection |
| `business-logic` | 비즈니스 로직 |
| `misconfiguration` | 보안 설정 오류 |
| `prototype-pollution` | Prototype Pollution |

- 이름은 ADR 020처럼 공격 이름은 영어(SQL Injection, Path Traversal), 나머지는 한국어(접근 제어, 정보 노출)로 썼다
- 미정(결정 필요): 보이는 순서. 안: SQL Injection, NoSQL Injection, XSS, SSTI, 접근 제어, 인증·세션, 비즈니스 로직, Command Injection, Path Traversal, 파일 업로드, SSRF, CSRF, XXE, 역직렬화, Prototype Pollution, 보안 설정 오류, 정보 노출(비슷한 주제끼리 붙임). 아니면 기존 12개 뒤에 다섯을 붙임

## 이유

- 문제를 수백 개로 늘릴 것을 기준으로 메인 화면과 목록을 만들었고([ADR 016](016-fe-디자인-방향.md)), 분류는 등록 시점에 표기를 고정하는 DB 테이블이라 문제가 생기기 전에 미리 넣어 둔다
- LLM 프롬프트 인젝션은 실습 환경 조건(외부 통신 차단, 디스크 2Gi)으로는 만들 수 없다

## 결과

- 백엔드: 분류 테이블 migration(ADR 020대로 be PR). 문제가 없는 분류도 필터와 내 기록 분석에 0으로 보인다
- 소개 화면의 분류 타일 12개는 그대로 둔다(2026-11-26 사람이 결정)
