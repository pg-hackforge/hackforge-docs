# 027. fe 실습·관리 화면

- 상태: 채택
- 날짜: 2026-11-22

## 배경

v1 백엔드 기능(#8~#13)이 모두 끝나 학습자와 관리자 화면을 만든다. 홈, 문제 목록, 실습 화면(공격 대상, 코드, 기록)은 2026-11-18 디자인 확정 때 캡처가 있다([ADR 016](016-fe-디자인-방향.md), hackforge-fe `design/screens/`). 문제 상세, 내 실습 기록, 관리자 세션 화면은 캡처가 없다.

확정한 홈과 문제 목록에는 내 진행 상태(끝내지 못한 문제, 분류별 완료, 내 상태 필터)가 있는데, 문제별 내 상태를 주는 API가 없다. 마감은 2026년 12월 초다.

## 선택지

1. 내 진행 상태: 백엔드 API를 더함 / v1 홈에서 빼고 v1.1
2. 화면 확인: 캡처가 있는 화면은 캡처대로, 없는 화면은 지금 화면 규칙대로 만들고 PR 스크린샷으로 리뷰 / 화면마다 시안을 먼저
3. 순서: 문제 목록·상세 → 실습 화면 → 홈 → 내 실습 기록 → 관리자 / 홈부터
4. 라이브러리: 터미널 xterm.js, 편집기 Monaco(번들에 포함, 코드 화면에서만 불러옴), Markdown react-markdown(날 HTML 끔)
5. 경로: `/problems` → `/problems/:id` → `/labs/:id`
6. mock: 새 API 모두와 터미널(MSW WebSocket mock의 가짜 셸)
7. 문서: docs 이슈 하나와 `specs/lab-ui/tasks.md` 하나

## 결정

모두 첫 번째 선택지로 한다(2026-11-22 사람이 결정).

### 내 진행 상태

- 문제별 내 상태: 내 세션 중 하나라도 실습을 완료했으면(`completed_at`) `COMPLETED`, 세션은 있지만 완료한 것이 없으면 `UNFINISHED`, 세션이 없으면 `NOT_STARTED`
- 문제 목록·상세 응답에 `myStatus`, 문제 목록에 `myStatus` 필터(여럿 고름)와 내 상태별 개수(facet, 다른 facet과 같은 규칙)
- `GET /api/me/progress`: 전체 문제 수, 완료 수, 끝내지 못한 수, 분류별 전체·완료 수(분류 표시 순서)
- 홈의 "끝내지 못한 문제"는 `myStatus=UNFINISHED`, "새로 추가된 문제"는 `sort=NEWEST`의 새 문제, "최근 기록"은 `GET /api/labs`로 만든다

### 화면

- 캡처가 있는 화면(홈, 문제 목록, 실습 화면)은 캡처와 `DESIGN.md`대로 만든다
- 캡처가 없는 화면(문제 상세, 내 실습 기록, 관리자 세션 목록·기록)은 문제 목록과 계정 관리 화면의 규칙(폭, 표, 상태 표시)을 따른다
- 시안 단계는 두지 않고 PR마다 화면 스크린샷(라이트·다크, 주요 상태)으로 리뷰한다
- 실습 화면과 메인은 최소 폭 1280px 기준이다(ADR 016)

### 경로와 흐름

- `/problems`(목록) → `/problems/:id`(설명과 [실습 시작]) → `/labs/:id`(실습 화면, 준비 중에는 준비 단계 표시)
- 진행 중인 실습이 있으면 홈과 상단 줄에 "실습으로 돌아가기"를 보여 준다. 다른 문제의 [실습 시작]은 진행 중 세션으로 안내한다(`LAB_ALREADY_ACTIVE`)
- `/records`(내 실습 기록)와 `/records/:id`(세션 하나의 기록), `/admin` 아래 세션 목록과 세션 기록

### 라이브러리

- 터미널: `@xterm/xterm`과 크기 맞춤 addon. 연결은 기존 WebSocket(ADR 022)
- 편집기: Monaco(ADR 024). 기본 설정의 외부 CDN 대신 번들에 넣고, 코드 화면을 열 때만 불러와 첫 화면 크기에 영향이 없게 한다
- Markdown(문제 설명, 힌트, 해답): `react-markdown`. 날 HTML은 표시하지 않는다(문제 내용의 HTML이 플랫폼 화면에서 실행되지 않게)

### mock

- 새 API는 모두 `src/mocks/handlers.ts`에 생성 타입으로 응답을 둔다. 실습 시나리오(준비, 공격, 방어, 완료, 종료)를 mock 패널에서 바꾼다
- 터미널은 MSW WebSocket mock으로 입력을 받아 간단히 답하는 가짜 셸을 둔다

## 이유

- 1: 확정한 디자인을 그대로 지키고, 내 세션을 문제별로 묶어 세는 조회라 비용이 작다
- 2: 마감까지 화면이 많다. 디자인 방향과 주요 화면은 이미 확정했고, 사람은 화면으로 리뷰한다
- 3: 실습 화면이 가장 크고 위험하다. 먼저 끝내야 일정이 밀려도 핵심 기능이 남는다
- 4: 셋 다 React에서 가장 널리 쓰는 선택이다. 연구실 서버에서 외부 CDN에 의존하지 않는다
- 6: 백엔드 없이 화면 상태별 확인과 스크린샷을 할 수 있다(fe-setup에서 정한 방식)

## 결과

- 백엔드: `openapi.yaml`(내 상태, 필터·facet, 진행 요약)과 구현
- fe: 문제 목록·상세, 실습 화면, 홈, 내 실습 기록, 관리자 세션 화면. 작업 목록은 `specs/lab-ui/tasks.md`
- 화면을 다 만들면 #8~#13의 화면 쪽 완료 기준을 확인하고 이슈를 닫는다
