# 016. fe 디자인 방향

- 상태: 채택
- 날짜: 2026-11-18

## 배경

fe 뼈대(hackforge-fe #7)가 끝났고, 화면을 만들기 전에 배치와 색을 정해야 한다. [ADR 015](015-fe-스택.md)는 디자인 방향을 첫 화면 이슈에서 정하기로 미뤄 두었는데, 실습 화면, 메인, 소개 화면이 같은 틀을 써야 해서 한 번에 정한다.

제약과 조건은 다음과 같다.

- fe는 사람이 실제 화면을 보고 리뷰한다. 그래서 글로 고르지 않고 실제 크기의 HTML 시안을 띄워 비교했다(2026-11-16~18). 시안은 hackforge-fe의 Impeccable 작업 폴더(`.impeccable/`, 저장소에 넣지 않음)에서 만들었다
- 브랜드 기준(hackforge-fe `PRODUCT.md`): Linear, Vercel, Raycast 수준의 마감. 대장간 비유(달굼, 담금질, 각인)는 로고, 진행 표시, 통과 표시 같은 디테일에만 쓴다. 해커 영화 같은 과장, 어린이 교육용 느낌, 평범한 관리자 화면은 피한다
- 실습 화면에는 공격 대상 화면, 웹 터미널, 웹 IDE, 힌트, 검증 결과가 모두 들어가야 한다
- v1 문제는 2~3개지만 문제는 계속 늘어난다
- 라이트·다크 테마 구조는 fe 뼈대에 이미 있다

## 선택지

실습 화면 배치

1. IDE처럼 여러 영역을 한 화면에 나눠 동시에 보는 배치
2. 한 작업만 화면 가득 보는 배치
3. 둘을 섞은 배치(A안): 왼쪽 레일로 한 화면을 골라 크게 보고, 코드 화면은 IDE 형태

색

1. 흑연과 불씨: 따뜻한 흑연 회색 + 불씨 주황
2. 청색 불꽃: 차가운 회색 + 파랑
3. 구리와 녹청: 돌빛 회색 + 구리, 통과는 녹청
4. 라이트는 무채색(흑백 시안 값)에 주황을 점으로만, 다크는 흑연과 불씨
5. 완전 무채색

테마

1. 라이트·다크 두 개, 둘 다 브랜드 색을 입힘
2. 라이트·다크·컨셉 세 개

## 결정

### 배치

| 화면 | 결정 |
|---|---|
| 실습 | A안. 레일 항목은 문제, 공격 대상, 코드, 터미널, 힌트, 기록. 상단 줄에 단계 표시(공격, 방어, 방어 검증), 재배포, 초기화, 주 버튼(단계에 따라 공격 검증 요청 또는 방어 검증 요청), 실습 종료. 하단 상태 막대에 단계, 마지막 검증, 자동 종료까지 남은 시간, 사용자. 공격 단계에서는 레일의 코드가 잠긴다 |
| 코드(실습) | 탐색기, 편집기 탭, 경로, 미니맵, 줄 번호, 수정한 줄 표시, 편집기 상태 줄. 틀(탐색기, 탭 줄, 상태 줄)과 편집기 면, 줄 번호 칸, 현재 줄을 색으로 구분한다 |
| 터미널(실습) | 여러 탭, 자주 쓰는 명령 패널 |
| 메인(로그인 후) | 문제가 수백 개로 늘어나는 것을 기준으로 한다. 홈에는 지금 할 것만 둔다(진행 중인 실습, 끝내지 못한 문제, 새로 추가된 문제, 분류별 진행, 최근 기록). 전체 문제는 문제 목록에서 검색, 필터(분류, 난이도, 내 상태), 정렬, 페이지로 찾는다. 내 기록도 필터와 페이지를 둔다 |
| 소개(로그인 전) | 반응형(1024px, 640px 구간). 구간 순서는 첫 화면, 미리 보기, 실습 방식, 검증, 실습 환경, 문제, 마무리. 효과는 아래 "소개 화면" 항목. 맨 아래에 개발자 표시(이름, 연락처)와 HTML `meta author` |

실습 화면과 메인은 큰 화면 기준(최소 폭 1280px)으로 만든다.

### 색

흑연과 불씨. 값은 아래와 같고, 정식 값은 hackforge-fe `src/index.css` 토큰과 `DESIGN.md`에 둔다.

| 역할 | 라이트 | 다크 |
|---|---|---|
| 바탕 | `#F5F5F4` | `#0F0F10` |
| 면 | `#FFFFFF` | `#161618` |
| 선택·채움 | `#EBEAE8` | `#232326` |
| 선 | `#E4E3E0`, `#D3D1CD` | `#2A2A2E`, `#38383D` |
| 글자 | `#17171A` | `#EDEDEF` |
| 보조 글자 | `#5C5B60` | `#A2A2A8` |
| 흐린 글자 | `#7E7E85` | `#85858D` |
| 강조(불씨) | `#E8590C`, 위 글자 `#FFFFFF` | `#FF7A33`, 위 글자 `#1A0D05` |
| PASS | `#2B8A3E` | `#51CF66` |
| FAIL | `#C92A2A` | `#F0566A` |
| 터미널 | `#141416` | `#0B0B0C` |

- 강조색은 주 버튼, 로고 표시, 현재 단계, 편집 커서, 수정한 줄 표시, 진행 막대, 입력 칸 포커스에 쓴다
- 터미널과 빌드 로그는 두 모드 모두 어두운 배경이다
- 공격 대상 화면 안의 웹 페이지는 문제의 서비스 자체라 우리 테마를 따르지 않는다

### 테마

라이트·다크 두 개이고 둘 다 흑연과 불씨를 입힌다. 처음 접속하면 운영체제 설정을 따르고, 사용자가 바꿀 수 있다(ADR 015와 같음). 테마를 더 두는 것은 토큰 구조로 나중에 할 수 있다.

### 로고

모루와 불티. 모루 실루엣은 글자색이고, 그 위로 튀는 불티 하나만 불씨 그라데이션(`#FFE29A` → `#FF8A3D` → `#D9480F`)이다. 도형이 단순해 16px 아이콘에서도 알아볼 수 있다.

### 소개 화면

소개 화면은 대장간 컨셉(달구고, 두드리고, 식힌다)을 크게 보여 주는 곳으로 둔다. 실습 화면과 메인은 지금처럼 비유를 디테일에만 쓴다. 효과는 처음 한 번 재생되거나 스크롤에 맞춰 움직이고, 계속 반복하는 것은 미리 보기와 판정 카드뿐이다.

| 구간 | 결정 |
|---|---|
| 첫 화면 | 헤드라인 "Strike hot / Fix cold"(Geist). 망치 3박자로 첫 줄이 내려앉고 hot이 체리빛 → 주황 → 흰빛으로 달아오름. 스크롤하면 달군 쇠 색 순서로 식음. 둘째 줄은 강철빛이고 광택이 한 번 지나감. 헤드라인 뒤로 불티가 떠오름 |
| 미리 보기 | 공격 → 코드 수정 → 재배포 → 같은 공격이 막힘을 줄여서 반복 재생. 공격이 통하면 로그인 카드 테두리가 붉게 달아올랐다 식음 |
| 실습 방식 | 화면을 고정한 채 단계가 바뀜. 단계 선이 달궈지며 채워지고 단계 번호가 각인처럼 찍힘. 구간에 다시 들어오면 다시 보임 |
| 검증 | 판정 카드가 한 줄씩 채워져 FAIL, 이어서 다시 검증해 PASS와 각인. 각인은 영어만(고리 글자 Cinzel, 가운데 블랙레터 "Tempered") |
| 실습 환경 | 그림 카드(격리, 외부 차단, 준비 시간, 자동 정리)가 차례로 떠오르고 숫자가 올라감 |
| 문제 | 분류 타일이 숯불처럼 한 번 달아올랐다 식음 |
| 마무리 | 회원가입 버튼 테두리를 따라 불씨가 돎. 맨 아래 HACKFORGE 글자에 꾸덕한 쇳물이 꿀렁이며 차오름 |
| 전체 | 위쪽 진행선과 구간 구분선은 템퍼링 색(밀짚 `#F6EBB8` → 갈색 → 보라 → 파랑 → 회색 `#8E949C`)으로, 위는 뜨겁고 아래로 갈수록 식은 색. 다크 모드 배경 양옆에 옅은 연기 결. 주 버튼을 누르면 작은 불티, 얇은 충격파, 버튼이 달았다 식음, 살짝 흔들림 |

- 소리는 쓰지 않는다. CC0 모루 녹음과 합성 소리를 모두 시험했지만 품질이 만족스럽지 않았고, 여럿이 쓰는 수업 환경에서 거슬릴 수 있다(2026-11-18 사람이 결정)
- 운영체제의 동작 줄이기 설정을 켜면 효과를 모두 끄고 내용만 보여 준다
- 소개 화면의 시연에는 실제 문제의 공격 문자열이나 해답을 쓰지 않는다. 공격 입력은 가린 글자로만 보여 준다

### 화면 검토에서 정한 기능 동작

시안을 검토하며 화면만이 아니라 동작도 정했다. 각 기능을 설계할 때 그 이슈의 작업 목록에 반영한다.

| 기능 | 정한 동작 |
|---|---|
| #8 공격 대상 화면 | 주소창은 호스트를 고정하고 경로만 입력받는다. fe는 경로만 보내고, 백엔드는 그 학습자의 실습 Pod 웹 서비스로만 전달한다 |
| #10 방어(웹 IDE) | 편집 내용은 자동 저장한다. 파일별로 처음 상태로 되돌릴 수 있다. `Dockerfile`, `Dockerfile.base`, `compose.yaml`, `init.sql`은 읽기 전용으로 표시한다 |
| #11 방어 검증 | 방어 검증 요청에는 단축키를 두지 않는다(공격 검증만 `Ctrl+Enter`). 요청 전에 남은 시도 횟수와, 재배포하지 않은 수정이 있으면 경고를 보여 준다. 검증 중에는 진행 상태를 보여 주고 중복 요청을 막는다. 아직 통하는 공격은 개수를 먼저 보여 주고 내용은 학습자가 요청할 때 공개한다. 통과한 뒤에도 해답을 볼 수 있다 |
| 실습 공통 | 실습 종료와 초기화는 확인 창을 거친다. 공격 단계의 초기화는 선택지 없이 확인만 받는다 |
| 문제 형식([ADR 014](014-challenge-형식과-등록.md) 후속) | 분류, 난이도, 예상 시간을 문제 정보에 추가한다. 문제 목록 API는 검색, 필터, 정렬, 페이지를 지원한다 |
| 실습 환경 | 환경 준비 중 세부 단계를 학습자에게 보여 줄 수 있게 한다 |

## 이유

- A안: 실습은 한 번에 한 작업(공격, 코드 수정, 검증 확인)에 집중하는 흐름이라, 작은 영역 여러 개보다 고른 화면을 크게 보는 편이 낫다. 코드 화면은 개발 학습자에게 익숙한 IDE 형태가 가장 빨리 읽힌다. 레일에 글자 라벨을 붙여 처음 쓰는 사람도 헤매지 않는다
- 메인: 문제를 카드로 다 펼치면 수백 개에서 쓸 수 없다. 홈은 다음 행동만 보여 주고, 찾기는 목록 화면에 모은다
- 흑연과 불씨: 이름의 대장간을 색 하나로 은은하게 드러낸다. 청색은 흔한 개발 도구처럼 보이고, 구리와 녹청은 차분하지만 강조가 약하다. 라이트를 무채색으로 두는 안(4)과 완전 무채색(5)도 비교했지만, 두 모드가 같은 따뜻한 흑연 톤과 주황을 유지하는 원래 값을 골랐다(2026-11-18 사람이 결정). 원래 값에서 다크 FAIL 색(주황과 덜 헷갈리게), 흐린 글자 대비, 공격 대상 화면의 테마 제외만 고쳤다
- 테마 두 개: 컨셉 테마를 따로 두면 대부분의 사용자가 기본값을 바꾸지 않아 브랜드 색을 못 본다. 화면마다 테마 세 개를 맞추는 작업량도 크다
- 소개 화면만 반응형: 처음 오는 사람은 휴대폰으로 볼 수 있지만, 실습 화면은 IDE와 터미널을 쓰는 작업 화면이라 큰 화면이 전제다
- 소개 화면의 컨셉 효과: 처음 오는 사람에게 "공격하고, 고쳐서, 막혔는지 확인한다"는 서비스와 이름(Hackforge)을 한 번에 기억시키려고 소개 화면에서만 비유를 크게 쓴다(2026-11-18 사람이 결정). 작업 화면은 집중이 우선이라 브랜드 기준대로 디테일에만 둔다. 깨지는 파편, 화면 전체 불티, 큰 번쩍임처럼 과한 효과는 시안에서 빼고 남은 것만 정했다

## 결과

- hackforge-fe에서 색 토큰(`src/index.css`), `DESIGN.md`, `PRODUCT.md`를 정리한다([specs/fe-setup/tasks.md](../specs/fe-setup/tasks.md) 작업 6). `PRODUCT.md`의 브랜드 항목("로고 없음", "비유는 디테일에만")을 로고와 소개 화면 예외에 맞게 고친다
- 화면 검토에서 정한 기능 동작은 #8, #10, #11, 문제 형식, 실습 환경 이슈를 설계할 때 반영한다. 문제 정보에 분류, 난이도, 예상 시간이 들어가면 백엔드 API와 Challenge 형식이 함께 바뀐다
- 라이트 모드 주 버튼(`#E8590C` 위 흰 글자)의 대비는 3.6:1로 웹 접근성 기준(본문 글자 4.5:1)보다 낮다. 원래 색을 유지하기로 했고, 접근성 점검 때 다시 본다

## 정정

- 2026-11-26: 소개 화면을 만들며 사람이 다음을 바꿨다(hackforge-fe #32). 세부 값은 hackforge-fe `DESIGN.md` "소개 화면"과 "소개 화면 효과"에 있다
  - 소개 화면은 앱 테마와 상관없이 다크로만 보인다. 효과와 확정 시안 색이 다크에서 맞춰져 있어서다
  - 미리 보기와 제품 화면 캡처에 실제 문제의 공격 문자열이나 고친 코드가 보여도 된다. 해답 문서 내용은 쓰지 않는다
  - 헤드라인은 "Strike Hot / Fix Cold", Geist 800으로 시안보다 크게(후보 5개를 같은 첫 화면에 입혀 비교해 정함)
  - 누름 효과(작은 불티, 얇은 충격파)는 주 버튼이 아니라 화면 빈 곳을 누를 때 나오고, 버튼·링크를 누를 때는 없다. 버튼이 달았다 식는 효과는 뺐다
  - 마무리 구간의 가입 단계 표시(회원가입 → 관리자 승인 → 문제 골라 시작)는 뺐다
  - 문구는 ADR 019 해요체와 앱 용어로 맞추고, 서비스 소개 위주로 다시 썼다
