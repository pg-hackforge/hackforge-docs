# 030. 내 기록 분석

- 상태: 채택
- 날짜: 2026-11-25

## 배경

내 실습 기록([ADR 026](026-관리와-기록.md), [ADR 027](027-fe-실습-관리-화면.md))은 세션 목록과 세션 하나의 기록만 보여 준다. 화면 검토(hackforge-fe #28)에서 목록이 밋밋하고, 지난 실습을 모아 보면 무엇을 잘하고 무엇이 부족한지 알 수 없다는 의견이 나왔다.

홈의 "내 진행"(`GET /api/me/progress`)은 분류별로 완료한 문제 수만 센다. 같은 분류에서 해답을 보고 끝냈는지, 공격과 방어 중 어디서 막혔는지는 알 수 없다. 문제와 분류가 많아진 서비스를 기준으로 다른 학습 서비스와 연구를 조사했다.

- Hack The Box: 분류별 진행을 레이더 차트와 상위 10개 분류 막대로, 태그는 많이 익힌 순서로 보여 준다. 완료율 기반이다
- solved.ac: 태그 레이팅은 푼 문제 중 어려운 상위 50개 난이도의 합이다. 레이더 차트에는 주요 태그 8개만 올린다
- LeetCode: 주제별 푼 수를 기초·중급·고급으로 묶고, 난이도별 푼 수를 따로 보여 준다
- TryHackMe: 점수 하나(1~100)에 깊이(가장 강한 분야)와 폭(분야 수)을 넣는다
- 학습 대시보드 연구(open learner model): 학습자에게 자기 실력 모델을 보여 주면 돌아보기와 다음 계획에 도움이 된다. 다만 너무 잘게 쪼개거나 다른 사람과 비교하면 화면이 복잡해지고, 근거 데이터의 불확실성을 같이 보여 줘야 믿는다

Hackforge는 한 문제 안에 공격과 방어가 함께 있다. 다른 서비스는 문제를 풀었는지만 세지만, 여기서는 분류마다 공격과 방어를 따로 볼 수 있다.

## 선택지

1. 위치: 목록 위 요약 카드 / 내 기록 안의 [분석] 탭
2. 강약 표시: 점수 하나로 합침 / 분류마다 공격·방어 점수와 근거
3. 판정과 점수 계산: 백엔드 / fe(백엔드는 사실만)
4. 비교: 다른 학습자와 비교·순위 / 자기 기록만

## 결정

1은 [분석] 탭, 2는 분류마다 공격·방어 점수와 근거, 3은 fe, 4는 자기 기록만으로 한다(2026-11-25 사람이 mock 시안을 보고 결정).

### 화면

- 내 기록(`/records`)에 탭 두 개: [실습 기록](지금 목록)과 [분석](`/records/analysis`). 두 탭 모두 홈과 같은 폭(1240px) 두 열이다
- [실습 기록] 오른쪽 패널: 실습 수, 완료한 문제 수, 실습 시간, 최근 18주 날짜별 활동 칸, 분석의 핵심 한 줄(보완할 점, 없으면 강점). 그 줄을 누르면 [분석]으로 간다
- [분석]
  - 숫자: 완료한 문제/전체, 해답 없이 완료 비율, 시도한 분류/전체, 실습 수와 시간
  - 분류별 공격·방어: 가운데 분류 이름, 왼쪽 공격(`chart-1`), 오른쪽 방어(`chart-4`) 막대와 점수, 시도/전체. 열 이름을 붙이고, 안 해 본 분류도 빈 막대로 넣는다. 시도한 문제가 3개 미만인 분류는 흐리게. 줄을 누르면 그 분류의 문제 목록
  - 강점과 보완할 점: 각각 둘까지, 공격·방어·둘 다를 표시하고 숫자 근거를 붙인다
  - 추천 문제: 가장 보완할 분류에서 끝내지 못한 문제, 없으면 시작하지 않은 쉬운 문제. 추천 이유를 한 줄로
  - 최근 1년 날짜별 활동 칸
  - "어떻게 계산하나요"에 아래 점수 규칙을 그대로 보여 준다

### 점수 규칙(fe)

- 공격(문제 하나): 힌트 없이 성공 100, 공격 힌트 하나에 20씩 깎고 성공했으면 40 이상. 건너뛰었거나 성공하지 못했으면 0
- 방어(문제 하나): 해답 없이 완료 100, 방어 검증을 한 번 더 할 때 10, 방어 힌트 하나에 15씩 깎고 50 이상. 해답을 본 뒤 완료 30, 끝내지 못함 0
- 분류 점수: 그 분류에서 시도한 문제의 점수를 난이도 무게(입문 1, 초급 1.5, 중급 2, 고급 3)로 평균한다
- 분류 순서: 공격·방어 평균 × 시도한 문제 수 / (시도한 문제 수 + 2). 많이 해 보고 잘한 분류가 위, 안 해 본 분류는 맨 아래
- 강점: 시도한 문제 3개 이상, 공격·방어 모두 75 이상. 보완할 점: 시도한 문제 3개 이상, 공격이나 방어가 60 미만. 둘 다 낮으면 한 줄에 둘 다
- 규칙은 실제 데이터가 쌓이면 조정한다. fe만 바꾸면 된다

### API

`GET /api/me/activity`(로그인한 학습자 본인). 판정하지 않고 사실만 준다.

- `totalChallenges`와 `categories[]`(key, name, 공개 문제 수): `GET /api/me/progress`와 같은 기준
- `sessions`, `totalMinutes`: 생성 실패(`FAILED`)를 뺀 내 세션 수와 시작부터 종료(진행 중이면 지금)까지 시간의 합(분)
- `days[]`: 최근 365일 날짜(`Asia/Seoul`, `YYYY-MM-DD`)별 시작한 세션 수(생성 실패 제외). 오래된 날부터, 0인 날도 넣는다
- `challenges[]`: 결과가 난 세션(끝났거나 완료한 세션, 생성 실패 제외)이 있는 문제마다 한 줄. 완료하지 않은 진행 중 세션은 아직 결과가 없어 넣지 않는다
  - 문제 id, 제목, 분류, 난이도, 그 문제의 결과가 난 세션 수
  - 가장 좋은 세션 하나의 `result`(`COMPLETED`, `COMPLETED_AFTER_SOLUTION`, `UNFINISHED`), 공격(`passed`, `skipped`, 공격 힌트 수), 방어(검증 횟수, 방어 힌트 수)
  - 가장 좋은 세션: 결과(해답 없이 완료 > 해답 확인 후 완료 > 끝내지 못함), 같으면 힌트가 적은 순, 방어 검증이 적은 순, 최근 순

## 이유

- 1: 분석은 내용이 많아 목록 위에 두면 목록을 밀어낸다. 탭이면 둘 다 제자리가 있고, 목록 쪽 패널의 한 줄로 분석의 존재를 알린다
- 2: 점수 하나는 무엇이 부족한지 감춘다. 공격·방어를 나누는 것이 Hackforge만 보여 줄 수 있는 정보이고, 근거를 붙여야 학습자가 납득한다
- 3: 판정 규칙은 데이터가 쌓이며 바뀔 가능성이 크다. 사실만 받으면 규칙을 바꿀 때 백엔드를 다시 배포하지 않는다. 응답은 시도한 문제 수만큼이라 작다
- 4: 실습 교육에서는 자기 성장이 중요하고, 비교는 화면을 복잡하게 만든다는 연구 결과가 있다. 연속 실습일처럼 압박을 주는 지표도 넣지 않는다
- 시도한 문제가 적은 분류를 흐리게 하고 순서에서 낮추는 것은 적은 표본으로 강약을 말하지 않기 위해서다

## 결과

- 백엔드: `openapi.yaml`에 `GET /api/me/activity`와 응답 스키마, 집계 쿼리(마이그레이션 없음)
- fe: 내 기록 탭과 두 열 배치, [분석] 탭, 점수 규칙(`src/lib`)과 테스트, mock 응답
- 나중에 같은 API로 fe만 더할 수 있는 것: 난이도별 완료, 월별 성장 추이(해답 없이 완료 비율, 방어 검증 평균)
- product.md 학습자 유스케이스에 "내 분석"을 더한다
