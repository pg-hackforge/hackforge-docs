# 004. 학습자 로컬 연결: HTTPS 터널 CLI

- 상태: 채택
- 날짜: 2026-11-02

## 배경

학습자가 웹 화면뿐 아니라 자기 PC의 도구(브라우저, Burp, sqlmap, ssh, VS Code Remote-SSH)로도 공격하고 코드를 고칠 수 있게 하려 한다. 실습 환경과 학습자 로컬을 이어야 하는데, 다른 학습자의 환경이나 클러스터 내부로는 닿지 않아야 한다. 일정은 v1(약 2달) 이후인 v1.1이다.

## 선택지

1. **사용자별 VPN** (WireGuard, OpenVPN): 연결하면 학습자 PC가 실습망 안에 들어간다. HackTheBox·TryHackMe 방식이다.
2. **오버레이 네트워크** (Headscale): 실습 Pod와 학습자 PC를 같은 사설망에 넣고 ACL로 제한한다.
3. **HTTPS 터널 CLI** (`hackforge connect`): 플랫폼 로그인으로 WebSocket을 열고, 로컬 포트를 실습 환경의 포트에 연결한다. 예: `localhost:8080` → Target, `localhost:2222` → Pod의 sshd

## 결정

3번을 택한다.

## 이유

- **격리를 새로 만들지 않는다.** 웹 터미널과 같은 경로(로그인 → `userId → sessionId → namespace → pod` 확인 → Kubernetes API)를 그대로 쓴다.
- **VPN은 격리를 다시 만들어야 한다.** VPN 서버를 Pod 하나로 두면 모든 학습자의 트래픽이 그 Pod의 IP로 나와서, NetworkPolicy로 사용자를 구분할 수 없다. 사용자별 규칙을 VPN 서버에서 직접 관리하거나 사용자마다 VPN과 UDP 포트를 따로 둬야 한다.
- **443만 쓴다.** UDP 포트를 열 필요가 없고, VPN을 막는 학교망·회사망에서도 동작한다.
- **필요한 기능이 다 된다.** 이 플랫폼의 로컬 작업은 웹 공격과 코드 수정이다.
- **도구가 이미 있다.** client-java에 포트 포워딩 API가 있다.

## 결과

- 전체 네트워크 접근이 아니므로 nmap으로 망을 스캔하는 문제는 낼 수 없다. 망 스캔이나 여러 호스트를 침투하는 문제가 필요해지면 2번(Headscale)을 다시 검토한다.
- 작은 CLI를 만들어 배포하고 유지해야 한다.
- VS Code Remote-SSH를 쓰려면 실습 Pod 안에 sshd가 있어야 한다. SSH 포트 포워딩은 Pod의 NetworkPolicy 안에서만 동작하므로 Default Deny가 그대로 적용된다.
- 플랫폼 서비스 계정에 `pods/portforward` 권한이 필요하다.
- 터널 연결도 유휴 판단의 '입력'에 포함한다.
