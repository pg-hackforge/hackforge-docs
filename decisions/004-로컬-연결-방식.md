# 004. 학습자 로컬 연결: HTTPS tunnel CLI

- 상태: 채택
- 날짜: 2026-11-02

## 배경

학습자가 웹 화면뿐 아니라 자기 PC의 도구(브라우저, Burp, sqlmap, ssh, VS Code Remote-SSH)로도 공격하고 코드를 고칠 수 있게 하려 한다. 실습 환경과 학습자 로컬을 연결하되, 다른 학습자의 환경이나 클러스터 내부로는 닿지 않아야 한다. 일정은 v1(약 2달) 이후인 v1.1이다.

## 선택지

1. 사용자별 VPN(WireGuard, OpenVPN): 연결하면 학습자 PC가 실습망 안에 들어감. HackTheBox·TryHackMe 방식
2. overlay network(Headscale): 실습 Pod와 학습자 PC를 같은 사설망에 넣고 ACL로 제한
3. HTTPS tunnel CLI(`hackforge connect`): 플랫폼 로그인으로 WebSocket을 열고, 로컬 포트를 실습 환경 포트에 연결. 예: `localhost:8080` → Target, `localhost:2222` → Pod의 sshd

## 결정

3번을 택한다.

## 이유

- 웹 터미널과 같은 경로(로그인 → `userId → sessionId → namespace → pod` 확인 → Kubernetes API) 재사용. 격리 로직을 따로 만들 필요 없음
- VPN은 격리를 다시 만들어야 함. VPN 서버를 Pod 하나로 두면 모든 학습자 트래픽이 그 Pod IP로 나와 NetworkPolicy로 사용자를 구분할 수 없고, 사용자별 규칙을 VPN 서버에서 직접 관리하거나 사용자마다 VPN과 UDP 포트를 따로 둬야 함
- 443 포트만 사용. UDP 포트를 열지 않아도 되고, VPN을 막는 학교·회사 네트워크에서도 동작
- 이 플랫폼의 로컬 작업은 웹 공격과 코드 수정이라 tunnel로 충분함
- client-java에 port forwarding API가 이미 있음

## 결과

- 전체 네트워크 접근이 아니라서 nmap으로 망을 스캔하는 문제는 낼 수 없다. 망 스캔이나 여러 호스트를 침투하는 문제가 필요해지면 2번(Headscale)을 다시 검토한다.
- 작은 CLI를 만들어 배포하고 유지해야 한다.
- VS Code Remote-SSH를 쓰려면 실습 Pod 안에 sshd가 있어야 한다. SSH port forwarding은 Pod의 NetworkPolicy 안에서만 동작하므로 Default Deny가 그대로 적용된다.
- 플랫폼 service account에 `pods/portforward` 권한이 필요하다.
- tunnel 연결도 idle 판단 입력에 포함한다.
