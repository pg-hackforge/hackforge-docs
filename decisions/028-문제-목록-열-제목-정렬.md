# 028. 문제 목록 열 제목 정렬

- 상태: 채택
- 날짜: 2026-11-22

## 배경

문제 목록은 정렬 드롭다운(새로 추가된 순, 쉬운 순, 짧은 순)으로 정렬한다([ADR 020](020-문제-정보와-목록-API.md), 확정 캡처 `main-problems-*`). 화면을 만든 뒤 검토에서, 표 모양 목록이라 열 제목을 눌러 정렬하는 편이 낫지 않냐는 의견이 나왔다(hackforge-fe #20 검토).

조사한 내용은 다음과 같다.

- 데이터 표 화면은 열 제목을 눌러 정렬하는 것이 기본 패턴이다. 정렬할 수 있는 열 제목은 버튼으로 두고 지금 정렬과 방향을 표시한다(Chrome 웹 UI 가이드, W3C APG sortable table)
- 정렬 기준이 화면의 열과 맞지 않으면 드롭다운이 낫다(GitLab 이슈 논의). 문제 목록의 정렬 기준(추가 순서, 난이도, 예상 시간)은 모두 열(번호, 난이도, 예상)과 맞는다
- 지금 API는 기준마다 방향이 하나라 "어려운 순", "긴 순", "오래된 순"을 못 한다

## 선택지

1. 드롭다운 그대로
2. 열 제목 정렬(번호, 난이도, 예상), 드롭다운 없앰, API에 반대 방향
3. 둘 다

## 결정

2로 한다(2026-11-22 사람이 결정).

- 정렬할 수 있는 열은 번호(`NEWEST`), 난이도(`DIFFICULTY`), 예상(`TIME`). 분류와 내 상태는 여럿을 고르는 값이라 왼쪽 필터가 맡고 정렬하지 않는다
- 열 제목을 누르면 그 기준의 기본 방향(새로 추가된 순, 쉬운 순, 짧은 순), 같은 열을 다시 누르면 반대 방향(오래된 순, 어려운 순, 긴 순)
- 정렬할 수 있는 열 제목에는 흐린 화살표를 늘 보여 누를 수 있음을 알리고, 지금 정렬 중인 열은 방향 화살표를 진하게 표시한다. 열 제목은 버튼이고 표에는 `aria-sort`를 둔다
- `GET /api/challenges`에 `reverse`(boolean, 기본 false)를 더한다. true면 그 정렬의 반대 방향이다. 동점은 지금처럼 새로 추가된 순으로 정한다(반대 방향이어도 동점 순서는 그대로)
- 정렬 드롭다운은 없앤다. ADR 020의 정렬 값(`NEWEST`, `DIFFICULTY`, `TIME`)은 그대로 쓴다

## 이유

- 표 모양 목록에서 열 제목 정렬이 가장 익숙하고, 정렬 기준이 모두 열과 맞는다
- 문제가 수백 개로 늘면 어려운 문제나 긴 문제부터 보는 일이 생긴다
- 같은 일을 하는 컨트롤을 두 개 두면 상태를 맞춰야 하고 화면이 복잡해진다

## 결과

- 백엔드: `openapi.yaml`에 `reverse`, 정렬 SQL에 반대 방향
- fe: 문제 목록의 열 제목 정렬(hackforge-fe #20에 반영), 확정 캡처와 달라진 점은 `DESIGN.md`에 적는다
