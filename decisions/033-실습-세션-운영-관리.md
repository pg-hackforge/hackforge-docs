# 033. 실습 세션 운영 관리

- 상태: 채택
- 날짜: 2026-11-27

## 배경

#94(실습 세션 운영 관리)에서 관리자가 여러 세션을 한 번에 끝내고, 끝낸 이유를 학습자에게 알리고, 문의나 장애 때 세션 안을 본다. Hackforge는 학교 안 도구가 아니라 공개 웹 서비스로 운영하는 것을 기준으로 한다(2026-11-27 사람이 정함). 시연용 경로는 따로 두지 않는다.

이미 정한 것은 다음과 같다.

- 관리자는 세션 목록(진행 중 기본, 전체)을 보고 세션 하나씩 강제 종료한다. 종료 사유는 `ADMIN`이고 학습자 화면에는 "관리자가 실습을 종료했어요"만 보인다([ADR 026](026-관리와-기록.md))
- 조회 API(세션, 검증, 재배포·초기화, 힌트, 상태 기록)는 관리자에게 열려 있고, 바꾸는 요청(검증, 파일, 재배포, 초기화, 종료)은 세션 주인만 받는다(ADR 026)
- 상태 기록 `session_events`의 주체는 `LEARNER`, `ADMIN`, `SYSTEM`이고 transaction에 적어 둔 값을 trigger가 쓴다(ADR 026)
- 터미널은 연결마다 exec로 새 셸을 열고, 백엔드가 WebSocket을 중계한다([ADR 022](022-공격-대상과-웹-터미널-연결.md))
- 파일 저장은 충돌을 409로 막고, 재배포·초기화는 세션당 작업 하나만 받는다([ADR 024](024-방어-IDE-재배포-초기화.md))
- 실습 화면은 `READY`인 동안 세션을 10초마다 다시 읽는다
- 공지·점검(#95, [ADR 034](034-공지와-점검.md))은 점검 시작 때 진행 중 세션을 끝낸다

## 선택지

1. 여러 세션 종료: 하나씩만 / 고른 세션과 진행 중 전체를 한 번에
2. 종료 안내: 사유만 / 관리자가 적은 문구도
3. 관리자 세션 보기: 기록만(지금) / 현재 상태 읽기 전용 / 터미널 실시간 보기 / 관리자 직접 조작
4. 터미널 보기와 조작의 동의: 관리자가 바로 / 학습자 수락 / 학습자 수락과 긴급 우회
5. 관리자 조작 뒤 검증: 점수에서 빼고 표시 / 점수에 넣고 표시 / 점수에 넣고 표시 없음
6. 학습자에게 메시지 보내기: 지금 / 나중

## 결정

1은 한 번에, 2는 문구도, 3은 네 단계 모두, 4는 읽기 전용은 관리자가 바로 보고 터미널 보기와 조작은 학습자가 수락했을 때만(긴급 우회 없음), 5는 점수에 넣고 표시, 6은 나중으로 한다(2026-11-27 사람이 결정. 3은 추천(읽기 전용까지)보다 넓게 정했고, 5는 추천(점수에서 뺌)과 다르게 점수에 넣되 표시는 남기는 중간안으로 정함).

### 일괄 종료

- `POST /api/admin/labs/terminate`: 고른 세션 id 목록 또는 "진행 중 전체"와 안내 문구(선택)를 받는다. 대상 중 종료 전 세션을 `TERMINATING`(`ADMIN`)으로 바꾸는 조건부 update 하나이고, 바뀐 수와 이미 끝나 건너뛴 수를 준다
- "진행 중 전체"는 요청 시각에 종료 전(`DELETED`, `FAILED` 제외)인 세션이다
- 환경 삭제는 지금처럼 reconciler가 한다. 관리자 화면은 대상 세션 중 아직 `TERMINATING`인 수와 끝난 수를 다시 읽어 진행 상황으로 보여 준다
- 관리자 화면은 실행 전에 대상 수를 보여 주는 확인 대화상자를 띄운다
- 점검 시작 때의 자동 종료(ADR 034)도 같은 서비스를 사유 `MAINTENANCE`로 쓴다

### 종료 안내 문구

- 세션 하나 종료와 일괄 종료 모두 안내 문구(일반 텍스트, 200자 이하, 선택)를 받아 `lab_sessions.end_message`에 저장한다
- 세션 응답에 `endMessage`를 더한다. 학습자 실습 화면의 종료 안내와 내 실습 기록, 관리자 세션 기록에 보인다
- 문구가 없으면 지금처럼 사유별 기본 안내만 보인다

### 관리자 세션 보기

관리자 세션 기록 화면에서 진행 중 세션이면 [실습 보기]로 실습 화면과 같은 배치의 관리자 화면을 연다. 해답은 지금처럼 보이지 않는다.

| 단계 | 할 수 있는 것 | 조건 |
|---|---|---|
| 읽기 전용 | 실습 단계, 파일 목록과 내용, 원본 대비 수정한 줄, 빌드 로그, 검증 결과 | 관리자가 바로. 열람 기록이 남음 |
| 터미널 보기 | 학습자 터미널 출력을 실시간으로 봄. 입력은 못 함 | 학습자 수락 |
| 조작 | 터미널 보기에 더해 관리자 자기 셸, 파일 저장, 재배포, 초기화, 공격 대상 열기 | 학습자 수락 |

- 조작에 검증 실행, 힌트 열기, 건너뛰기, 해답 열기는 넣지 않는다. 학습자의 학습 행동이라 학습자만 한다. 종료는 관리자 강제 종료를 쓴다
- 읽기 전용 열람은 관리자가 그 세션의 파일이나 빌드 로그를 처음 읽을 때 서버가 기록한다(같은 관리자와 세션은 1시간에 한 번). 학습자에게 알림은 띄우지 않고, 내 실습 기록에 "관리자가 실습 내용을 봤어요"로 보인다
- 관리자 셸은 학습자 셸과 따로 새로 열린다. 파일 동시 수정은 기존 409, 재배포·초기화는 기존 세션 작업 잠금이 막는다
- 관리자의 조작도 활동으로 쳐서 idle 시간을 늘린다
- 관리자가 한 재배포·초기화는 그 기록에 요청한 관리자를 남긴다

### 요청과 수락

- 관리자가 종류(터미널 보기, 조작)와 사유(200자 이하, 필수)를 적어 요청한다. 세션 하나에 열린 요청이나 허락은 하나만 있다. 터미널 보기 허락 중에 조작을 요청할 수 있고, 수락하면 조작으로 바뀐다
- 학습자 실습 화면은 세션 응답의 요청을 보고 관리자 닉네임, 종류, 사유와 [수락]·[거절] 대화상자를 띄운다. 10초 주기로 읽으므로 늦어도 10초 안에 뜬다
- 2분 안에 답이 없으면 서버가 만료로 본다. 학습자가 실습 화면을 열어 두지 않았으면 그 사이 열었을 때만 뜬다
- 허락은 학습자가 [그만 보게 하기]를 누를 때, 관리자가 [끝내기]를 누를 때, 세션이 `READY`가 아니게 될 때 중 먼저 오는 때 끝난다. 끝나면 관리자 터미널 보기와 관리자 셸 WebSocket을 서버가 닫는다
- 허락된 동안 학습자 화면 위에 "관리자 ○○님이 터미널을 보고 있어요" 또는 "관리자 ○○님이 조작 중이에요"와 [그만 보게 하기]가 계속 보인다
- 요청, 수락, 거절, 만료, 끝은 모두 시각과 함께 남고 내 실습 기록과 관리자 세션 기록에 보인다
- 수락 없이 터미널 보기나 조작을 여는 긴급 우회는 두지 않는다. 학습자가 수락하지 않는 경우(악용 조사 등)는 읽기 전용 보기와 강제 종료로 대응한다

### 터미널 보기

- 백엔드가 학습자 터미널 WebSocket을 중계할 때 출력을 허락받은 관리자 보기 WebSocket에도 복사해 보낸다. 관리자가 붙은 뒤의 출력만 보이고, 터미널 내용은 저장하지 않는다
- 학습자가 다시 연결해 새 셸이 열리면 관리자 보기도 새 셸 출력을 따라간다

### 관리자 조작 뒤 검증

- 조작 허락이 처음 시작된 시각 뒤에 실행한 검증은 응답에 `afterAdminControl`을 준다. 저장한 값이 아니라 허락 기록에서 계산한다
- 실습 화면 검증 결과, 내 실습 기록, 관리자 세션 기록에 "관리자 조작 뒤"를 표시한다
- 내 기록 분석 점수에는 그대로 넣는다. 순위표나 수료증처럼 공정성이 중요한 기능을 만들 때 다시 정한다

### 권한

- 모두 `ADMIN` 역할만 쓴다. 출제자는 포함하지 않는다
- 학습자 수락 API는 세션 주인만 받는다

## 이유

- 1: 클러스터 이상 같은 장애 때 세션을 하나씩 끝낼 수 없고, 점검 자동 종료와 같은 코드를 쓸 수 있다. 환경 삭제가 이미 reconciler의 비동기 작업이라 별도 작업 큐가 필요 없다
- 2: 지금은 학습자가 왜 끝났는지 모른다
- 3·4: 문의 대응과 문제 오류 확인에는 현재 상태가 필요하다. 파일과 기록은 학습자가 남긴 결과물이라 바로 보되 기록을 남기고, 터미널처럼 지금 하는 행동을 보거나 세션을 바꾸는 일은 원격 지원 도구처럼 본인이 수락해야 한다. 이용약관에 고지할 내용도 단순해진다
- 5: 관리자 조작은 대부분 고장 난 문제 환경을 고쳐 주는 일이라 점수에서 빼면 학습자에게 불리하다. 표시를 남겨 두면 나중에 공정성이 중요한 기능에서 가려낼 수 있다
- 6: 공지 띠(ADR 034)와 종료 안내 문구로 대부분 대신한다

## 결과

- 백엔드: `openapi.yaml`(일괄 종료, 종료 문구, 관리자 파일·빌드 로그 읽기 허용, 요청·수락·거절·끝내기, 세션 응답의 요청·허락, 검증 `afterAdminControl`, 터미널 보기 WebSocket), migration(`lab_sessions.end_message`, 관리자 열람·요청·허락 기록 표, 재배포 기록의 요청 관리자)
- 터미널 보기 중계는 백엔드 인스턴스 하나를 전제로 한다. 백엔드를 여러 대로 늘릴 때(roadmap "그 뒤") 인스턴스 사이 전달 방식을 다시 정한다

- 이용약관과 개인정보 처리방침(v1.1 배포 준비)에 관리자 열람과 수락 뒤 조작을 고지한다
- product.md 관리자 유스케이스와 데이터 모델에 더한다
