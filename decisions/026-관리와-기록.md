# 026. 관리와 기록

- 상태: 채택
- 날짜: 2026-11-22

## 배경

#13(관리와 기록)에서 관리자는 진행 중인 세션을 보고 강제 종료하고, 세션 기록(검증, 재배포)을 조회한다. 세션 상태가 바뀔 때마다 이전 → 다음 상태, 주체, 시각을 남기고, Pod·컨테이너 CPU·메모리를 보는 observability 대시보드를 둔다(product.md 유스케이스 10~12, SessionEvent 개념).

이미 정한 것은 다음과 같다.

- 세션 상태는 `CREATING`, `INITIALIZING`, `READY`, `TERMINATING`, `DELETED`, `FAILED`이고 reconciler와 API가 조건부 update로 바꾼다. 종료 사유는 `USER`, `IDLE`, `POD_LOST`([ADR 012](012-실습-환경-수명-주기.md), [ADR 025](025-방어-검증과-해답.md))
- 터미널은 세션이 `READY`가 아니게 되면 서버가 닫는다([ADR 022](022-공격-대상과-웹-터미널-연결.md))
- 검증, 힌트 공개, 재배포·초기화, 실습 완료, 해답 열람은 이미 각자 시각과 함께 남는다(ADR 023, ADR 024, ADR 025)
- 해답 열기(`POST`)는 `READY`일 때만 받고, 종료한 세션의 해답은 이 기능에서 정하기로 했다(ADR 025)
- 개발 클러스터 노드는 2 core, 메모리 4GB이고 metrics-server와 StorageClass가 없다. 운영 서버는 메모리 32GB 예정이다(2026-11-22 사람이 알림)
- 운영 HTTPS와 도메인은 v1.1이다(#74)

## 선택지

1. 세션 목록: 진행 중 기본에 "전체"와 페이지 / 진행 중만
2. 강제 종료 사유: 새 값 `ADMIN` / 기존 `USER`
3. 상태 기록: DB trigger(주체는 transaction에 적어 둠) / 상태를 바꾸는 코드마다 기록. 기록 대상: 상태 변경만 / 학습 이벤트까지
4. 기록 조회: 관리자만 / 학습자도 자기 기록("내 실습 기록")
5. 관측성: metrics-server와 관리자 화면의 현재값 / Prometheus와 Grafana(이력) / v1.1로 미룸
6. 권한: 관리자만 / 출제자도

## 결정

1은 진행 중 기본에 전체와 페이지, 2는 `ADMIN`, 3은 DB trigger와 상태 변경만, 6은 관리자만으로 한다. 4는 학습자도 자기 기록을 보고, 그 세션에서 열었던 해답도 다시 볼 수 있게 한다. 5는 Prometheus와 Grafana를 가볍게 설치한다(2026-11-22 사람이 결정. 4와 5는 추천과 다르게 정함).

### 관리자 세션 목록과 강제 종료

- `GET /api/admin/labs`: 기본은 종료 전 세션(`DELETED`, `FAILED` 제외), `status=ALL`이면 전체. 최근 시작 순, 페이지는 문제 목록과 같은 방식
- 한 줄: 세션 id, 학습자(닉네임, 이메일), 문제, 상태와 준비 단계, 학습 단계(공격, 방어)와 완료 여부, 시작·마지막 활동·종료 예정·종료 시각, 종료 사유
- `POST /api/admin/labs/{id}/terminate`: 종료 전 세션을 `TERMINATING`(`ADMIN`)으로 바꾼다. 학습자 종료와 같은 조건부 update이고, 이미 종료 중이거나 끝났으면 지금 상태를 그대로 준다. 터미널은 기존 규칙대로 닫힌다
- 학습자 화면은 종료 사유 `ADMIN`이면 "관리자가 실습을 종료했어요"를 보여 준다
- 관리자 API는 `ADMIN` 역할만 받는다(기존 `/api/admin/**` 규칙). 출제자는 포함하지 않는다

### 상태 기록(`session_events`)

- `lab_sessions`에 AFTER INSERT OR UPDATE trigger를 두고, `status`가 바뀔 때마다(생성 포함) 세션, 이전 상태(생성이면 null), 다음 상태, 주체, 주체 사용자 id, 시각을 `session_events`에 넣는다
- 주체는 요청을 처리하는 transaction이 `set_config('hackforge.actor', ...)`와 `hackforge.actor_user_id`로 적는다(`LEARNER`, `ADMIN`). 적혀 있지 않으면 `SYSTEM`(reconciler, 시작할 때 복구). transaction 범위 설정이라 다음 요청으로 새지 않는다
- 기록 대상은 상태 변경만이다. 단계 변경, 힌트, 검증, 재배포·초기화, 완료, 해답 열람은 이미 각자 시각과 함께 남아 있어서 기록 화면이 시간순으로 합쳐 보여 준다
- 기록은 지우지 않는다. 세션이 지워지면 함께 지워진다(사용자 삭제 시 세션과 함께)

### 기록 조회

- 학습자: `GET /api/labs`로 자기 세션을 최근 순으로(페이지) 본다. 세션 하나는 기존 조회 API(세션, 검증, 재배포·초기화, 힌트)로 끝난 세션도 본다(지금도 자기 세션은 종료 뒤 조회됨)
- `GET /api/labs/{id}/events`: 그 세션의 상태 기록을 시간순으로 준다
- `GET /api/labs/{id}/solution`: 그 세션에서 해답을 연 적이 있으면 상태와 상관없이 해답을 다시 준다. 연 적이 없으면 409 `SOLUTION_LOCKED`. 해답을 처음 여는 것은 지금처럼 `POST`(`READY`일 때만)다
- 관리자: 위 조회 API(세션, 검증, 재배포·초기화, 힌트, 상태 기록)를 모든 세션에 대해 쓸 수 있다. 바꾸는 요청(검증, 파일, 재배포, 초기화, 종료 등)은 지금처럼 세션 주인만 받는다. 관리자의 해답 조회는 넣지 않는다

### 관측성(Prometheus, Grafana)

- `monitoring` namespace에 Prometheus와 Grafana를 가볍게 설치한다. 노드 지표(node-exporter), 컨테이너 지표(kubelet cAdvisor), Kubernetes 오브젝트 상태(kube-state-metrics: 재시작, OOMKilled)를 수집하고 Alertmanager는 넣지 않는다
- 수집 간격 30초, 보존 7일. 저장은 노드 로컬 디스크다(StorageClass가 없어 hostPath PV)
- Grafana는 Kubernetes 컨테이너·노드 대시보드를 가져다 쓰고, 실습 namespace(`lab-*`)별 CPU·메모리를 볼 수 있게 한다
- Grafana는 외부에 열지 않고 관리자가 `kubectl port-forward`로 접속한다. 운영 HTTPS(#74) 뒤에 공개 방식을 다시 정한다
- 실습 Pod 안에서 compose로 띄운 서비스(web, db)별 값은 보이지 않는다. 실습 Pod의 컨테이너 단위까지다
- 설치 절차와 측정한 자원 사용량은 `infra/`의 runbook에 둔다

## 이유

- 1: 기록 조회를 하려면 끝난 세션도 찾을 수 있어야 한다
- 2: 학습자에게 종료 이유를 알려야 하고(product.md 예외 상황), 직접 끝낸 것과 구분해야 안내 문구를 달리 할 수 있다
- 3: 상태를 바꾸는 곳이 조건부 update 여러 군데(시작, 종료, reconciler, 다시 만들기)라 코드마다 넣으면 빠뜨리기 쉽다. trigger는 빠짐없이 남는다. 학습 이벤트는 이미 기록이 있어서 두 번 남기지 않는다
- 4: 학습자가 지난 실습에서 무엇을 했고 어떻게 고쳤는지 돌아볼 수 있다. 연 해답은 이미 본 내용이라 다시 보여 줘도 문제 풀이에 영향이 없다
- 5: 운영 서버(32GB)는 여유가 있고, 이력 그래프가 실측해서 정하기로 한 값(실습 디스크, 운영 생성 제한 시간, 정원)을 정하는 데 쓰인다. 대시보드 화면을 직접 만들지 않아도 된다
- 6: 지금 관리자 API와 같은 규칙이다
