# 008. 개발 VM 실행 환경: Hyper-V, 디스크는 SSD

- 상태: 채택
- 날짜: 2026-11-03

## 배경

[ADR 005](005-실습-환경-실행-기반.md)는 개발 VM을 VirtualBox에 NAT + Host-only 네트워크로 두기로 했다. 2026-11-02 이 구성에서 `kubeadm init`이 두 번 실패했다(#5).

- 개발 PC는 WSL2와 VBS(가상화 기반 보안) 때문에 Windows hypervisor가 항상 돈다. 그래서 VirtualBox가 AMD-V를 직접 못 쓰고 Windows hypervisor API(NEM)를 거쳐 실행된다. VirtualBox 로그: `Attempting fall back to NEM: AMD-V is not available`
- 이 상태에서 guest vCPU가 최대 241초 동안 멈췄다(`watchdog: BUG: soft lockup - CPU#1 stuck for 241s!`). idle 상태인 `swapper`에서도 멈췄으므로 guest 부하 때문이 아니다.
- Hyper-V로 옮긴 뒤에도 VM 디스크가 HDD에 있을 때는 4KB sync write가 평균 약 95ms 걸렸고, CPU 부하와 겹치자 VM이 38초 동안 멈췄다. etcd는 fsync 지연에 민감하다.

## 선택지

1. VirtualBox 유지, vCPU를 1개로 줄임
2. Windows hypervisor를 끔(`hypervisorlaunchtype off`, 메모리 무결성 끔)
3. VM을 Hyper-V로 옮김

## 결정

3번을 택하고, VM 디스크는 SSD에 둔다.

- Hyper-V Gen 1 VM, vCPU 2, 메모리 4GB 고정(동적 메모리 끔), checkpoint 끔
- 네트워크: Hyper-V internal switch + Windows NAT, guest는 고정 IP 하나
- 디스크: 호스트 SSD. HDD에는 두지 않음
- 사양(2 vCPU / 4GB)은 [ADR 006](006-개발-VM과-운영-서버.md) 그대로

## 이유

- 1번은 원인(NEM)이 그대로 남음. CPU 1개면 kubeadm preflight check도 무시해야 하고, Sysbox·Compose 테스트가 매우 느려짐
- 2번은 WSL2, Docker Desktop, Windows 보안 기능을 함께 잃음. 개발 PC에서 WSL2를 쓰고 있음
- 3번은 Windows 설정을 끄지 않아도 되고, Hyper-V는 Windows hypervisor 위에서 제 속도로 돎. 운영 서버는 실제 서버라 개발 VM의 hypervisor와 관계없음
- 측정값(같은 VM, Hyper-V):

  | 테스트 | HDD | SSD |
  |---|---|---|
  | 4KB sync write 60초 | 630회 (약 95ms/회) | 13,061회 (약 4.6ms/회) |
  | CPU 2개 100% + sync write 180초: 최대 지연 | 38,405ms | 225ms |

- 옮긴 뒤 `kubeadm init`은 7초 만에 끝남. VirtualBox에서는 4~5분 걸리다 실패했음

## 결과

- ADR 005의 "VM: VirtualBox, NAT + Host-only"를 이 ADR이 대체한다. ADR 005의 나머지(Ubuntu 24.04, kubeadm 1.35, containerd, Sysbox, Calico)는 그대로다.
- VM 디스크는 설치 때 최대 100GB dynamic disk로 잡혀 ADR 006의 40GB와 다르다. 2026-11-03 기준 실제 사용량은 8.4GB.
- Hyper-V를 켜고 VM을 만들려면 관리자 권한이 필요하다. 사용자 계정을 Hyper-V Administrators 그룹에 넣으면 이후 VM 관리는 관리자 권한 없이 된다.
- VirtualBox VM은 더 쓰지 않는다. 새 디스크는 기존 VirtualBox 디스크를 VHD로 복제해 만들었다.
