# 019. 화면 문구: 말투와 용어

- 상태: 채택
- 날짜: 2026-11-19

## 배경

fe 초기 구성(#45)과 계정 화면 시안(#53)의 문구가 영어 문장을 옮긴 것처럼 어색했다. "계정이 없나요? 가입 신청", "가입이 거절되었습니다. 문의는 관리자에게 해 주세요"처럼 주어와 피동이 영어식이고, 용어도 국내 서비스에서 쓰지 않는 말("가입 신청", "가입 메모")이 섞여 있었다. 백엔드 오류 메시지는 하십시오체인데, fe는 입력 칸 오류(`Problem.errors[].message`)를 그대로 보여 주므로 화면 하나에 말투가 섞일 수 있다.

## 선택지

말투

1. 해요체(토스, 카카오처럼 화면 문구 전체)
2. 하십시오체(은행 앱, 공공기관처럼)
3. 섞어 씀: 안내는 해요체, 오류와 확인은 하십시오체

## 결정

- 화면에 보이는 문구는 해요체로 쓴다. fe 문구와 백엔드 오류 메시지(`ErrorCode`의 title, 입력 칸 오류)가 모두 해당한다.
- 개인정보 수집·이용 동의처럼 약관 성격의 글은 하십시오체로 둔다([ADR 018](018-계정-화면.md)의 동의 문구).
- 문장은 국내 서비스에서 쓰는 구조로 쓴다.
  - 사람을 주어로, 능동으로 쓴다. "가입이 거절되었습니다" 대신 "가입이 승인되지 않았어요"
  - 할 일을 말한다. "이메일 또는 비밀번호가 맞지 않습니다" 대신 "이메일 또는 비밀번호를 다시 확인해 주세요"
  - 제목만으로 충분하면 설명을 붙이지 않는다
  - 확인 창의 실행 버튼은 동작으로 쓴다(`거절하기`, `변경하기`). 알리기만 하는 창은 `확인`
  - 화면에는 "백엔드" 대신 "서버"라고 쓴다
- 화면 용어는 아래로 한다. docs도 같은 말을 쓴다.

  | 대상 | 화면 용어 | 쓰지 않는 말 |
  |---|---|---|
  | 가입 | 회원가입 | 가입 신청 |
  | `/account` | 내 정보 | 내 계정 |
  | `/admin`, 상단 메뉴 | 회원 관리, 메뉴는 `관리자` | 계정 관리, 관리 |
  | 승인 상태 | 승인 대기, 승인 완료, 거절 | 승인됨, 거절됨 |
  | `signupNote` | 가입 메모(선택) | 남길 말 |
  | 역할(`role`) | 권한 | 역할 |
  | 테마의 system | 시스템 기본값 | 시스템 설정 |

- 역할(`role`)은 docs와 코드에서 "역할"로 둔다. docs가 "권한"을 Kubernetes RBAC와 접근 권한의 뜻으로 이미 쓰고 있어서, 데이터 이름까지 바꾸면 "권한을 빼도 예전 권한이 남음" 같은 문장이 헷갈린다. 화면 글자만 "권한"이다.
- docs, PR, 이슈의 문장은 지금처럼 "-다"와 개조식으로 쓴다. 해요체는 화면 문구에만 쓴다.

## 이유

- 해요체: 이 서비스를 쓰는 사람은 학생과 교육 참가자이고, 토스처럼 화면 전체를 해요체로 통일한 서비스가 늘었다. 하십시오체는 오류와 금지 문구가 딱딱하게 읽히고, 섞어 쓰면 같은 화면 안에서 말투가 바뀐다.
- 동의 문구는 하십시오체: 국내 서비스는 화면을 해요체로 써도 약관과 동의 문서는 대부분 하십시오체로 쓴다.
- 백엔드 오류 메시지까지 바꿈: fe가 입력 칸 오류를 그대로 보여 주므로 백엔드 문구도 화면 문구다. 화면 전체 오류(로그인 실패 등)는 fe가 `code`로 자기 문구를 고르지만, 백엔드 title도 같은 말투로 맞춰 두면 Swagger와 Postman으로 볼 때도 같다.

## 결과

- hackforge-fe `PRODUCT.md`의 말투 규칙을 해요체로 바꾸고, 이미 만든 화면(상단 줄, 사용자 메뉴, 안내 띠, 404·403·연결 실패)과 계정 화면 시안을 고친다.
- hackforge-be `ErrorCode`와 입력 칸 오류 문구를 해요체로 바꾼다. 기본 검증 문구는 `ValidationMessages.properties`에 두어 서버 JVM의 언어 설정과 관계없이 한국어로 나온다.
- 소개, 메인, 실습 화면 시안의 문구는 그 화면을 만들 때 이 규칙으로 고친다.
