# 034. 공지와 점검

- 상태: 채택
- 날짜: 2026-11-27

## 배경

#95(공지와 점검 안내)에서 관리자는 업데이트와 정책 변경을 공지하고, 점검을 미리 예고하고, 점검 중에는 서비스를 막는다. 공개 웹 서비스로 운영하는 것을 기준으로 하고 시연용 경로는 따로 두지 않는다(2026-11-27 사람이 정함). v1.1에 한다(2026-11-27 사람이 결정).

이미 정한 것은 다음과 같다.

- 관리자 화면은 제목 '관리자' 아래 탭으로 오간다. 지금 탭은 [실습 세션][회원]이다([ADR 027](027-fe-실습-관리-화면.md))
- 소개 화면은 로그인하지 않은 사람이 보는 첫 화면이고 자기 상단 줄을 쓴다([ADR 016](016-fe-디자인-방향.md))
- fe는 API 응답의 `Date` 헤더로 서버 시계를 보정한다(fe #33)
- Markdown은 react-markdown으로 보여 주고 raw HTML은 그리지 않는다
- 일괄 종료와 종료 사유는 [ADR 033](033-실습-세션-운영-관리.md)에서 정했다
- 메일 발송(#18)은 도메인(#74) 뒤라 점검 예고 메일은 이 기능에 넣지 않는다

## 선택지

1. 공지와 점검: 하나로 / 나눔
2. 점검이 막는 범위: 전체만 / 새 실습만과 전체 두 단계를 점검마다 고름
3. 진행 중 실습: 그대로 둠 / 미리 새 실습을 막고 경고한 뒤 시작 때 종료
4. 띠 닫기 기억: 브라우저 저장 / 서버에 사용자별 저장
5. 공지 목록·상세: 로그인한 사람만 / 공개
6. 화면 전달: 주기적으로 다시 읽음 / 서버가 밀어 줌(SSE)
7. 더 넣을 것: 임시 저장, 상단 고정, 점검 끝남 안내, 읽음 표시, 점검 기록 페이지, 고친 내용 전체 이력

## 결정

1은 나눔, 2는 두 단계, 3은 30분 전부터 새 실습을 막고 경고한 뒤 시작 때 종료, 4는 브라우저 저장, 5는 공개, 6은 주기적으로 다시 읽기로 한다. 7은 임시 저장, 상단 고정, 점검 끝남 안내만 넣고 읽음 표시, 점검 기록 페이지, 고친 내용 전체 이력은 나중에 한다(2026-11-27 사람이 결정, 모두 추천대로).

### 공지

- `notices`: 제목(100자 이하), 본문(Markdown, 20,000자 이하), 중요도(일반, 중요), 고정, 임시 저장 여부, 게시 시작 시각, 띠 표시 여부와 띠 내림 시각(비우면 관리자가 내릴 때까지), 만든·고친 관리자와 시각, 삭제 시각
- 보이는 상태는 값으로 정한다: 임시 저장, 예약(게시 시작 전), 게시 중, 띠 내림(목록에는 남음), 삭제
- 삭제는 실제로 지우지 않는다(soft delete). 지운 공지 상세 주소는 410 `NOTICE_DELETED`이고 fe는 "삭제된 공지예요"를 보여 준다
- 공지 목록 `/notices`와 상세 `/notices/:id`는 로그인 없이 본다. 고정 먼저, 그다음 게시 시작 최근 순이고 페이지는 문제 목록과 같은 방식이다. 소개 화면 맨 아래 줄과 사용자 메뉴에 링크를 둔다
- SPA라 검색 엔진용 서버 렌더링은 하지 않는다. 문서 제목만 공지 제목으로 바꾼다

### 상단 띠

- 앱 전체와 소개 화면 위에 보인다. 로그인하지 않아도 보인다
- 보일 수 있는 것이 여럿이면 점검 띠가 먼저이고, 공지는 중요 먼저, 같은 중요도면 최근 게시 하나만 띠에 보이며 "외 N개"로 공지 목록에 이어진다
- 일반 공지는 [닫기]로 닫고, 닫은 공지 id를 브라우저에 저장해 다시 띄우지 않는다(기기마다 따로). 저장이 안 되는 브라우저에서는 그 화면에서만 닫힌다
- 중요 공지와 점검 띠는 닫을 수 없다

### 점검

- `maintenances`: 제목, 안내 문구(일반 텍스트, 500자 이하), 막는 범위(새 실습만, 전체), 시작·끝 예정 시각, 예고 시작 시각(기본은 시작 72시간 전), 상태(예정, 진행 중, 끝남, 취소), 실제 시작·끝 시각, 만든 관리자
- 다른 점검(취소 제외)과 시간이 겹치면 409 `MAINTENANCE_OVERLAP`
- 예정 시각이 되면 백엔드의 주기 작업이 예정 → 진행 중, 진행 중 → 끝남으로 바꾼다. 백엔드가 꺼져 있다가 켜지면 그때 시각 기준으로 맞춘다
- 관리자 조작: [지금 시작](예정일 때), [지금 끝내기](진행 중일 때), [연장](끝 예정 시각을 늦춤), [취소](예정일 때), 수정(예정일 때만 모든 칸, 진행 중이면 끝 시각만)
- 상태가 바뀌거나 시각이 바뀔 때마다 이전·다음 값, 관리자 또는 시스템, 시각을 `maintenance_events`에 남긴다
- 점검 만들기와 상세에는 지금 진행 중인 실습 수와 관리자 세션 목록 링크를 보여 준다(ADR 033)

### 점검 중 실습

- 시작 30분 전부터 끝날 때까지 실습 시작은 거절한다. 시작 전에는 409 `MAINTENANCE_SCHEDULED`, 진행 중에는 503 `MAINTENANCE`이고 응답에 끝 예정 시각을 준다
- 시작 30분 전부터 진행 중 실습 화면에 "N분 뒤 점검으로 실습이 끝나요"를 보여 준다
- 점검이 시작되면 진행 중 세션을 ADR 033 일괄 종료로 끝낸다. 종료 사유는 새 값 `MAINTENANCE`이고 세션에 점검 id를 남긴다. 학습자 화면과 내 실습 기록은 점검 제목과 함께 "점검으로 실습이 끝났어요"를 보여 준다
- 두 범위 모두 같다. 새 실습만 막는 점검도 클러스터를 다루는 작업이라 진행 중 세션을 끝낸다

### 전체 막음

- 진행 중인 "전체" 점검이 있으면 관리자가 아닌 사용자의 API 요청은 503 `MAINTENANCE`(끝 예정 시각, `Retry-After`)를 받는다
- 막지 않는 API: 사이트 상태, 공지 목록·상세, 로그인, 로그아웃. 관리자가 아닌 사용자의 로그인은 비밀번호 확인 뒤 503으로 거절하고 세션을 만들지 않는다
- 관리자는 모든 API를 그대로 쓴다
- fe는 API가 503 `MAINTENANCE`를 주면 그 자리에서 "점검 중이에요" 화면(제목, 안내 문구, 끝 예정 시각)으로 바꾼다. 소개 화면은 그대로 보이고 띠만 점검 띠가 된다
- 점검이 끝난 뒤 30분 동안 "점검이 끝났어요" 띠를 보여 준다. 닫을 수 있다

### 화면 전달

- 공개 API `GET /api/site-status`가 지금 보일 공지 띠, 예고·진행 중 점검, 막 끝난 점검을 한 번에 준다
- fe는 앱을 열 때, 탭으로 돌아올 때, 5분마다 다시 읽는다. 받은 예고 시작·시작·끝 시각이 되면 그 시각에 맞춰 한 번 더 읽는다. 시각 비교는 보정한 서버 시계로 한다

### 관리자 화면

- 관리자 탭에 [공지][점검]을 더한다
- 공지: 목록(상태별), 만들기·수정(Markdown 편집과 띠·상세 미리 보기), 임시 저장, 예약 게시, 고정, 띠 내리기, 삭제
- 점검: 목록(상태별), 만들기·수정, [지금 시작], [지금 끝내기], [연장], [취소], 상세의 변경 기록
- 관리자 API는 `ADMIN` 역할만 받는다

### 이번에 하지 않는 것

- 백엔드가 꺼진 배포 중 점검 화면(reverse proxy의 고정 페이지, v1.1 배포 준비)
- 점검 예고 메일(#18 뒤), 여러 언어, 읽음 표시, 점검 기록 공개 페이지, SSE, 공지 고친 내용 전체 이력

## 이유

- 1: 공지는 보여 주기만 하는 글이고, 점검은 서비스를 막는 일정이라 상태와 영향이 다르다
- 2: 클러스터 작업은 실습만 막으면 되고, DB 작업은 서비스 전체를 막아야 한다
- 3: 점검이 시작되는 순간 실습이 갑자기 끊기면 학습자가 이유를 모른다. 시작 직전에 새 실습을 열어 곧바로 끊기는 일을 막고, 진행 중인 학습자에게는 하던 단계를 마무리할 시간을 준다
- 4: 닫기는 편의 기능이라 기기마다 따로여도 된다. 서버 저장은 읽음 표시를 만들 때 함께 한다
- 5: 공지는 로그인하지 않은 방문자도 봐야 하는 서비스 소식이다
- 6: 점검은 미리 예고하고 fe가 시각을 알고 있어 5분 주기와 시각 맞춤으로 충분하다
- 7: 넣은 셋은 관리자가 공지를 쓰고 운영하는 데 바로 필요하고, 나머지는 사용자가 늘어난 뒤에 필요하다

## 결과

- 백엔드: `openapi.yaml`(공지 공개·관리자 API, 점검 관리자 API, 사이트 상태, 실습 시작 거절 코드, 503 `MAINTENANCE`, 종료 사유 `MAINTENANCE`), migration(`notices`, `maintenances`, `maintenance_events`, 종료 사유와 세션의 점검 id), 점검 상태 주기 작업, 전체 막음 filter
- fe: 상단 띠, 공지 목록·상세, 점검 중 화면, 실습 화면 점검 경고와 종료 안내, 관리자 [공지][점검] 탭
- infra: 운영 runbook에 점검 절차(예고 → 점검 → 끝남 확인)
- product.md 관리자 유스케이스와 예외 상황, 데이터 모델에 더한다
