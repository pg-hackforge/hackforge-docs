# 029. 원본 읽기와 수정 표시

- 상태: 채택
- 날짜: 2026-11-23

## 배경

확정 캡처 `lab-code`의 코드 편집기에는 원본과 달라진 줄 표시(불씨색 막대)와 탐색기의 파일별 변경 표시(M, 현재 파일의 +4 −2)가 있다(`DESIGN.md` "코드 편집기"). 둘 다 문제의 원본 코드와 지금 코드를 비교해야 한다.

[ADR 024](024-방어-IDE-재배포-초기화.md)의 파일 API에는 원본으로 되돌리기만 있고 원본을 읽는 API가 없다. 되돌리기는 고친 내용을 지우므로 비교에 쓸 수 없다. 그래서 hackforge-fe #23(작업 7)에서는 두 표시를 빼고 만들었다.

## 선택지

1. 표시를 넣지 않는다
2. 원본 읽기 API를 더하고, 파일 목록에 원본과 다른지 여부를 넣는다. 줄 비교는 화면이 한다
3. 서버가 파일별 줄 비교 결과(diff)까지 준다

## 결정

2로 한다(2026-11-23 사람이 결정).

- `GET /api/labs/{id}/files/original?path=...`: Pod 안 `/hackforge/original`의 파일 내용과 SHA-256. 응답 모양과 규칙(READY, 방어 단계, 1MB 초과·바이너리 거절, 경로 검사)은 파일 읽기와 같다. 원본에 없는 파일(학습자가 만든 파일)은 404 `FILE_NOT_FOUND`. 활동으로 세지 않는다
- 파일 목록 `LabFileEntry`에 `modified`(boolean)를 더한다. `/app`의 파일이 원본과 내용이 다르거나 원본에 없으면 true. 목록을 만드는 같은 exec에서 `cmp`로 비교한다
- 화면은 연 파일 하나의 원본만 읽어 줄 단위로 비교한다. 편집기 왼쪽에 바뀐 줄과 더한 줄을 불씨색 막대로, 탐색기 아래에 지금 파일의 더한 줄·지운 줄 수를 보여 준다. 탐색기의 파일 이름 옆에는 `modified`면 M을 붙인다. 비교는 편집할 때마다 다시 하고 서버에 묻지 않는다

## 이유

- 원본은 이미 Pod 안에 있다(ADR 024). 읽기만 더하면 되고 새 저장소나 테이블이 필요 없다
- 탐색기의 M을 위해 파일마다 원본을 읽으면 파일 수만큼 요청이 나간다. 목록에서 한 번에 비교하면 exec 한 번이다
- 줄 비교는 입력할 때마다 바뀌어야 하므로 화면에서 한다. 서버 diff는 저장한 뒤에만 맞는다
- 3은 서버가 비교 알고리즘과 출력 형식을 정해야 하고, 화면의 입력 중 상태와 어긋난다

## 결과

- 백엔드: `openapi.yaml`에 원본 읽기와 `modified`, `LabCluster`에 원본 읽기, 파일 목록 스크립트에 비교
- fe: 원본과 줄 비교(`src/lib`), 편집기 막대, 탐색기 M과 +/− (hackforge-fe 작업 7 뒤 따로)
